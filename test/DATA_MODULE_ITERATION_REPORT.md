# 数据分析模块 · 五轮迭代循环结果报告

**日期**：2026-09-19　**对象**：新上线的数据分析模块（data.js）+ 全游戏回归
**循环标准**：每轮 = 房主托管位 + 5 名 subagent 玩家（Playwright 无头客人端）真实联机打牌 → 每人独立审计数据模块（程序化核账 data_audit + 截图人工判读 + 服务器留档交叉对账）→ 汇总修复 → 下一轮复验。
**产物**：`data1~5/<id>/`（截图+result.json）、`data1~5/<id>_review.md`（25 份玩家反馈）、`test/hand-logs/<房码>/`（服务器留档交叉证据）。

## 二、数据正确性终审（天证骑士 R5 口径）

- 断言三件套：noAssert=0 / badAssert=0 / sumMatch=true——五轮全部如此；
- 逐手全池对账：主池/边池分层手算严丝合缝（790=50+40+700 例）；
- VPIP/PFR：多人/单机、BB 过牌免计、limp 计入——口径教科书级；
- 翻前/翻后下注口径：**牌桌按钮、牌局日志、牌谱详情三处同源**；
- 底牌/隐私：muck 保护正确，摊牌公开信息入档合规。

## 三、五轮累计修复清单（全部落地并复验）

1. 客人端牌谱 assert 账目断言（Σ派彩=Σ投入，不平红字）
2. 记录 hero 归属 + 剥「（你）」（单机/多人双口径统一）+ mode 字段（mp/sp）
3. 去重键改 room#handNo#hero（跨设备导入不重复计费、他人视角不入个人曲线）
4. 牌谱详情：行动流人名化+按街分组+中文动作（弃牌/过牌/跟注 增量/下注/加注到）+胜负手行（同赢家多池合并带合计）+摊牌对手底牌
5. 数据页：4 列 KPI、720px 弹窗、内容自滚动、按钮 sticky 常驻、顶栏降权、范围筛选 chips（选中态）、曲线逐手圆点+悬停、对手表网格化+部员徽章+低样本门控、导入按钮描边、隐私文案修正
6. 结算金额终值直出（删 750ms 滚动假数）+ 脉冲高亮
7. 客人「下一局」请求协议（房主代点推进）+ 5s 超时恢复 + 按钮态复位
8. engine 无效过牌转弃记 fold（牌谱与钱一致）
9. join 拒绝文案诚实化 + 握手超时 15s + auto-next 手间停留 5s + 会话统计口径 tooltip + 落地页占位文案清理 + 多人局教练文案收敛

## 四、移交清单（本轮确认未修，按优先级）

1. **P1 留档单点+静默失败**（三轮连催）：服务器留档只有房主 POST 一条腿、失败静默、无 GET 审计端点——D2JBMA 房主 0 落盘无人知晓。改法：失败 appendError+重试队列；客人 POST perspective:'guest'；serve.js 增 GET /api/handlog?room=。
2. **P1 挂机托管钟 45s**（两轮连催）：挂机房主每手吃满 45s（会话时长的 66~75%）。改法：AFK 判定降钟至 5~8s，或托管节奏三档随房广播。
3. **P2 长牌谱展开尾部遮挡 ≤23px**：`nearest` 对超高元素忽略 scroll-margin（机制级）。改法：toggle 时量高差手动 scrollTop（8 行 JS，wupa 已给配方，落地后牌谱回看 9.4→9.5+）。
4. **P2 幽灵座位/代打无数据标记**：离席座自动弃手照入档稀释对手 VPIP、代打决策记进真人昵称。改法：record 加 idle/auto 标记，对手表加筛选。
5. **P2 结算弹层逐行浮现动画吃掉 5s 停留预算**：改终值渲染+从内容就绪起算。
6. **P3 打包**：曲线 x 轴刻度、对手表表头、chips aria-pressed、牌谱首行首屏可达性、导出文件名已修但无 GET 端点、mp_guest 指纹去重（工具侧）、翻前 bet/raise 引擎级区分、牌谱缺位置维度。
7. **非代码项**：学园风立绘统一度 +40 分但识别度 −15 分（葵夏肤色/凛发型/梅发色），建议旧装以皮肤形式回归（资产层，需 AI 重生成）。

## 五、结论

五轮循环把数据分析模块从「能对账的账本」（R1）推到「能复盘的牌谱+可信的战绩系统」（R5，呜帕终评 9.4/10）。数据正确性五轮零缺陷、零回归；所有修复均为小步+当轮复验；玩家反馈中两次「实锤 P0」经服务器留档交叉验证一真一假（假的那次避免了无谓改动）。剩余移交项已全部量化并可独立施工。
