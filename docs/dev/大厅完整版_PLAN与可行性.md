# 大厅完整版 PLAN 与可行性分析

> 2026-09-25 · 目标：把 v1 大厅壳升级到雀魂级"游戏大厅"体验
> 前置：v1 大厅壳已上线（角色舞台/服装页签/部员切换/顶栏统计/模式卡），牌面+立绘资产全量入库

## 一、可行性总结论

**可以做，且成本远低于预期。** 原因有三：

1. **立绘"活体系统"已经存在**：`portraits.css` 内置 `pt-breathe`（呼吸）/`pt-sway`（摇曳）/`pt-blink`（眨眼）/`pt-look`（视线）四套动画，每个角色有专属节奏参数（如铃眨眼 4.6s/凛 6.2s）。雀魂大厅的"角色活着"的感觉，我们换一个渲染函数就能拿到 80%。
2. **台词系统已经存在**：六人各有 win/lose 语音文本池 + COMFORT 安抚池，配表情资产可做点击互动。
3. **全部纯前端**：无后端、无账号、无服务器成本，localStorage 持久化，与现有 vanilla JS 栈零冲突，Steam 打包（Tauri）存档迁移路径已在 07 文档预留。

## 三、服装解锁系统（把"收集欲"做对，不做抽卡）

雀魂皮肤的驱动力是收集；我们不卖卡，用**游玩解锁**：

| 服装 | 解锁条件 |
|---|---|
| p0 默认服v4 | 初始解锁 |
| p1 部服v4 | 初始解锁 |
| p2 特色·和趣 | 该角色累计 10 手 |
| p3 特色·职业 | 该角色赢 5 手 |
| p4 特色·主题 | 该角色好感度 Lv.3（约 30 手） |

- 未解锁：图鉴/选人页显示**剪影 + 解锁条件**（ref-select 同款，CSS 现成模式）
- 数据全在 handlog/localStorage，判定纯前端
- ⚠️ 需要你拍板：要不要解锁制？（也有人偏好全开纯展示——两行代码的差别）

## 六、风险

1. **解锁节奏**定太紧会劝退、太松没动力——建议 p2=10 手 / p3=胜 5 手 / p4=好感 Lv.3 起步，玩两天可全开
2. **动画性能**：pt-breathe/sway 全员同屏已在座位实测过（动效降频方案现成），大厅只有 1 个大立绘，无压力
3. **存档**：localStorage 清浏览器数据即重置——Steam 打包时迁移到用户目录（07 文档已预留），现阶段可加"导出存档"按钮兜底
