## 一、现状审计（对着实测截图说话）

| 区块 | 现状 | 问题 |
|---|---|---|
| 场景 | 纯 CSS 渐变 + 椭圆 div 桌面 | 没有场景叙事，空得像后台调试页 |
| 座位 | 150px 小盒 + 66px 圆头像 + 文字 | 角色存在感弱，看不出"谁在打牌" |
| 公共牌/底池 | 图像牌 ✓ + 纯文本底池 | 底池没有视觉焦点，牌无槽位感 |
| 下注表现 | 纯数字 | 无筹码演出，输赢无质感 |
| 行动条 | 功能齐全的 CSS 按钮 | 与新视觉不配套 |
| 立绘 | 座位 -t 小图 ✓ · 玩家右侧 200px ✓ | 面板样式旧，表情无联动 |

**结论：牌、立绘两类核心资产已是新视觉，桌面层还停在旧后台风——重设计只动"桌面层"，不碰引擎/网络/教练逻辑。**

## 二、设计方向：「夜樱部室」

深夜的部室，樱树在窗外，一桌人打牌到天亮。三层视觉：

1. **背景层（AI 生成 · 合规）**：夜樱部室场景横图，月光从窗进来，中央压暗留给桌面 —— 参照 Boss 桌的"背景即氛围"
2. **桌面层（矢量/程序化）**：深藏青呢面椭圆桌 + 金色内沿双线 + 桌面樱纹水印（牌面同源五瓣樱），rim light 让桌从背景里"亮出来"
3. **信息层（克制）**：底池面板、座位板、行动条统一为"暗底 + 金线框 + 大数字（Constantia，与牌面同字体）"

配色沿用全站盘：象牙纸白 / 墨黑 / 樱红 / 金。

## 四、布局方案（6 人桌基准，4/2 人桌自适应）

```
┌──────────────────────────────────────────────┐
│ 顶栏（保留：手数/盲注/大厅/音量/重新开局）        │
│  ┌─────────────┐   [底池面板: 大数字+金框]     │
│  │ 座位板(左位) │                              │
│  │  ┌──────────────────────┐  ┌ 座位板(右位) │
│  │  │   椭圆桌(呢面+樱纹)    │  │  立绘胸像  ││
│  │  │  [公共牌 ◫◫◫◫◫ 金槽]  │  │  名字/筹码 ││
│  │  │   底池筹码堆           │  └───────────┘│
│  │  └──────────────────────┘                  │
│  │      [对手下注筹码堆×N]                     │
│  ├──────────────────────────────────────────┤
│  │ 玩家区: 手牌(放大110×156) · 行动条(大按钮)  │
│  └──────────────────────────────────────────┘
│  右侧: GTO 教练面板（保留，可折叠）              │
└──────────────────────────────────────────────┘
```

- **座位板**：胸像立绘（-t.webp）+ 名字 + 筹码数 + 状态条；行动中 = 金框呼吸，弃牌 = 去饱和压暗，ALL-IN = 红金火焰框
- **底池面板**：Boss 桌式 ornate 金框 + `底池 1,240` 大号数字（随手数增长有滚动动画）
- **下注筹码**：每个座位前按面值堆叠的筹码图 + 数额角标；结算飞向赢家
- **玩家手牌**：放大到 110×156，hover 微抬；行动条四按钮大尺寸 + 加注滑条

## 六、验收标准

1. 1920 / 1440 / 860 手机宽三档不破版
2. 公共牌最小 48px 可辨（沿用牌面铁律）
3. 自动跑完一整手：无 JS 错误、教练面板可用、留档正常
4. 新旧对比截图留档 `_shots/table-v2/`
5. AI 背景只做场景层；面板/筹码/按钮/字体全部程序化（矢量铁律）

## 七、风险与依赖

- **AI 背景质量**：场景图不合格就 CSS 渐变+樱纹兜底（不阻塞 P1）
- **表情联动**：依赖 portraits.js resolveExpr，win→happy 已有 API
- **性能**：背景用 CSS 固定层，筹码动效 transform/opacity（合成器路径），手机端动效降频沿用现有 matchMedia 方案
